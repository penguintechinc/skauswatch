# v2.1 Backlog

Items deliberately deferred out of v2.0 to protect the big-bang scope
(zero-schema-change invariant, "no new features in v2.0"). Each entry
records why it is safe to defer.

## Research router: live external lookups

`/api/v1/research/*` in v1 was entirely runtime-broken — every handler
raised `AttributeError` on the missing `config.research` attribute and
returned 500, and the client wiring (`_get_research_clients`) called
methods that do not exist. There is no working v1 behavior to preserve.

v2.0 ships the contract-decided deterministic surface (auth, validation,
shodan/maltego enable gates, exact `GET /config` payload, intended
empty-result envelopes). Implementing *working* WHOIS/DNS/ASN/Shodan/
Maltego lookups requires new network clients (DNS resolver, WHOIS, HTTP
integrations) — that is new functionality, not a port, so it lands in
v2.1 behind `skauswatch.research`.

Safe to defer: v2.0 is strictly better than v1 here (deterministic
envelopes instead of 500s); nothing customers currently rely on is lost.

## MySQL/MariaDB support (from the approved plan)

`DB_TYPE=mysql` deferred — no production MySQL head exists; sqlx AnyPool
sacrifices compile-time type safety. `skauswatch-db` trait surface keeps
it additive.

## Drop inert `alembic_version` tables

Left in place by the v2.0 sqlx-migrate baseline stamping; drop in v2.1.

## scanner ASM subsystem (LARGE)

v1 `scanner` had a full attack-surface-management subsystem:
`masscan`, `nuclei`, `openvas`, `zap`, `screenshot`, `cert_inspector`,
`banner_grabber` + their parsers (~15k LOC). The Rust port covers the
malware-scan path (YARA via yara-x 1.19.0 — EICAR-proven — + ClamAV
INSTREAM) fully.

**BUILT in v2.0 (Phase 12 / P12-A):** the ASM pipeline is functional —
masscan enumeration, `banner_grabber`, TLS `cert_inspector`, diff-vs-prior,
and headless-chromium `screenshot` capture — all tenant-scoped and DB-backed
(`asm_*` tables, migration 0006), driven by the manager `asm` router
publishing `scanner:tasks` (the old proxy-to-a-nonexistent-HTTP-server is
gone).

**Still unbuilt:** `nuclei`/`zap`/`openvas` standalone scan types — v1 had
them but with NO trigger/client path (unreachable), so they are not a cutover
blocker; disposition TBD (not auto-deferred to v2.1 at this time).

## sshca

- RSA CA-key support: blocked on `ssh-key` 0.7 going stable (0.7.x is
  RC-only; house rules forbid pre-release). v2 is Ed25519/ECDSA-only with
  a fail-loud RSA rejection at startup. (v1's SSH CA emitted invalid
  certs for all key types, so nothing regressed.)
- Durable ssh-cert storage: v1 kept issued certs in memory (no table);
  v2 preserves that. Add a migration + table for persistence.
- ssh-keygen interop test in CI (the emitted certs are verified against
  real OpenSSH manually + structurally; add an automated interop test).

## Vault cloud sync — Azure/GCP/Oracle/Kubernetes providers

`services/worker-vault-sync` ports the v1 `CloudProvider` interface and
implements AWS Secrets Manager fully (`aws-sdk-secretsmanager`, real
push/pull/delete/list). Azure Key Vault, GCP Secret Manager, Oracle Cloud
(OCI) Vault, and Kubernetes Secrets are wired through the same factory
(`get_provider`) but return `ProviderError::NotImplemented` for every
operation (`providers/not_implemented.rs`) rather than a working
integration — porting four more cloud SDKs (Azure `azure_security_keyvault`,
GCP `google-cloud-secretmanager-v1`, OCI via `reqwest` + request signing,
Kubernetes via `kube`) was out of scope alongside the crypto gate and full
REST backend port in one pass. Each pin should land as its own reviewable
change.

## Vault sync — no producer ever sends a real secret payload (pre-existing v1 gap, preserved)

Discovered while porting `sync-worker/worker.py`: `_do_push`/`_do_delete`
expect message fields (`secret_id`, `secret_name`, `encrypted_value`,
`encrypted_dek`, `dek_version`, `external_ref`) that **no v1 caller ever
publishes**. The only producer, `POST /sync/integrations/{id}/trigger`
(`api/v1/sync.py::_publish_sync_event`), sends only `{integration_id,
event_type, timestamp}`. A manual trigger therefore always logs a decrypt
failure and skips — in v1 and in the v2 port, which preserves this exactly
(`services/vault/src/routes/sync.rs`, `services/worker-vault-sync/src/
handler.rs`). Wiring a real payload (publish on secret create/rotate, or
have the worker fetch-and-decrypt by `secret_id` instead of trusting the
stream message) is new functionality, not a port, and belongs in v2.1.
