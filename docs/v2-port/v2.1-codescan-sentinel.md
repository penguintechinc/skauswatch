# CodeScan Sentinel — AI-assisted dependency & vulnerability management

**Status:** Draft design spec · **Target:** v2.1+ (net-new; must not ride the v2.0 cutover) · **Flag:** `skauswatch.codescan.sentinel` (default OFF)

A Dependabot alternative — and more — built into the CodeScan module (Darwin-origin). It periodically scans configured repos' default + latest release branches, finds outdated deps, known CVEs, SAST issues, license violations, and leaked secrets, **triages them by reachability + severity**, and either documents / alerts / opens a grouped fix PR — all governed by an admin-defined policy engine and rolled up into security/executive reports.

## 1. Premise — AI-assisted, tools-first

Deterministic OSS tools are the **eyes**; the LLM is the **brain** that reasons on their output. The LLM never does raw detection (non-reproducible, incomplete, costly) — tools detect, the LLM judges.

```
1. TOOLS (deterministic, parallel, cheap) ─► normalized findings + cheap static prefilter
2. LLM on that output + code context: correlate/dedupe · false-positive filter ·
   reachability + exposure · severity contextualization · remediation · explanation
3. policy engine ─► actions {alert │ fix-batch │ document} ─► findings store ─► reports
```

**Why it matters:** findings stay **auditable + reproducible** — the tool hit is ground truth; the AI verdict is a *traceable judgment on top of it* (a security team sees "gosec flagged X → AI: unreachable → documented", not an opaque LLM scan). Cross-tool agreement becomes a confidence signal. And it lifts the existing product for free: CodeScan's current review reads the diff cold; feeding it the same tool hits sharpens every ordinary review too.

## 2. Platform boundaries — consume, don't reimplement

SkausWatch (the security foundation, since 2018) and WaddleAI (the AI ecosystem, 2026) cross-consume; each is authoritative in its own domain and neither reimplements the other's.

| | Sentinel |
|---|---|
| **Owns** | scanner orchestration, normalization, reachability logic, policy engine, findings store, reports, fix-PRs |
| **Consumes** | **AI inference + guardrails from WaddleAI** (models, routing, ShieldGemma + prompt-injection defense); git creds + repo config (existing); IceBox for its own secrets |
| **Exposes** | findings / posture data (consumable by WaddleAI, a central dashboard, SIEM) |

Cross-product calls (SkausWatch→WaddleAI for inference; WaddleAI→IceBox for secrets) are **service-to-service over the v2.0 SPIFFE/SVID mesh** — the same identity fabric validated against AWS STS. No static shared secrets.

## 3. Scanner tool layer (pluggable registry, OSS/OSI only, non-PRC)

Add a scanner → normalize its output → the AI layer absorbs it. Tools are toggled per-repo via the policy engine.

| Dimension | Tools (license) |
|---|---|
| SAST | semgrep (LGPL) · gosec (Apache) · bandit (Apache) · ruff (MIT) · eslint-security (MIT) |
| SCA / CVE | trivy (Apache) · osv-scanner (Apache) · grype (Apache) · govulncheck (BSD) · cargo-audit · pip-audit · npm audit · OWASP Dependency-Check |
| Secrets | gitleaks (MIT) · trufflehog (AGPL, subprocess-only) |
| IaC / K8s / container config | trivy config · checkov (Apache) · kube-linter (Apache) · hadolint (GPL) |
| Container image | trivy image · grype · clair · dockle |
| SBOM | syft (Apache) · cdxgen (Apache) · trivy SBOM — *revives the dropped v1 `CycloneDXScanner` intent; feeds compliance reports* |
| License | (existing deps.dev) · trivy license · scancode-toolkit |
| Repo posture | OpenSSF Scorecard (Apache) |

**Excluded:** CodeQL, Snyk (restrictive/commercial); any PRC-origin tooling. Scanners run as isolated K8s Jobs / sibling containers.

**Boundary:** DAST (OWASP ZAP, nuclei) is *dynamic* (needs a running target) — out of scope for Sentinel, but note SkausWatch's Scanner/ASM module already has nuclei/zap concepts, so static (CodeScan) + dynamic (Scanner) is a future combined-risk story.

## 4. AI layer — via WaddleAI

CodeScan sends "triage this finding, tier N" to WaddleAI; WaddleAI owns model selection/routing and guardrails. Implemented as a **`WaddleAI` provider in `skauswatch-ai`** (already abstracts Anthropic/OpenAI/Ollama).

| Concern | Owner |
|---|---|
| Model hosting + routing (tiers, escalation) | WaddleAI |
| Guardrails — ShieldGemma + prompt-injection defense on untrusted repo content | WaddleAI |
| Prompt construction (repo content as **data, never instructions**) | Sentinel |
| Strict output schema (finding-verdict objects, not free-form actions) | Sentinel |
| Tool finding = ground truth (AI re-ranks, can't erase a scanner hit) | Sentinel |
| Human-gate on auto-fix PRs | Sentinel |

**Model routing (WaddleAI-side config; landscape as of 2026-08):** bulk ~80% (dedupe/format/FP-filter) → **Gemma 4 E4B** (4.5B eff, 128K ctx, native thinking mode, Apache-2.0; ~10–15% better than Gemma 3 4B on reasoning/code; Ollama-hostable); reason ~15% (reachability/exposure) → **Gemma 4 26B MoE** (4B active, 256K ctx); hard ~5% (critical + reachable, patch-gen, report narrative) → frontier via API where code-egress is allowed. Alt small tier: Phi-4-mini (3.8B, MIT). **Never PRC-origin** (Qwen/DeepSeek/GLM/Yi — supply-chain rule). No Google security-tuned *code* model exists (CodeGemma = codegen, ShieldGemma = content-safety); a security-specialized fine-tune (e.g. a G4-E4B derivative) is a later evaluation, not a dependency.

**Threat note — the tool is an attack surface:** it ingests untrusted repo content and takes automated actions (PRs). Assume repo content is hostile (prompt-injection in comments / package names to hide a vuln or poison a fix). WaddleAI's guardrails + Sentinel's structural defenses (data-not-instructions, strict schemas, ground-truth anchoring, human-gate) bound the blast radius.

## 5. Reachability + severity triage

1. **Static prefilter (cheap, deterministic):** is the package even imported? is the affected symbol referenced? — kills most noise for free, before any LLM spend.
2. **AI triage (survivors only):** is the call site reachable from an exposed entrypoint, can external input reach it? → `{used, reachable, exposure}`.

Default action matrix (overridable — see §6):

| | Reachable + external | Reachable + internal | Not used / dead path |
|---|---|---|---|
| Critical/High | **alert + fix** | fix | document |
| Med/Low | fix | document | document |

## 6. Policy engine

Admin-defined, priority-ordered rules override the default matrix; first match wins, else fall back to the matrix. Every decision is **audit-logged** (why a finding was auto-fixed vs. suppressed).

- **Match on:** repo · ecosystem · package · CVE · severity · reachability · exposure · tool.
- **Action:** `ignore | document | alert | fix`.
- **Blast radius = opt-out:** every configured CodeScan repo is watched by default; admin explicitly exempts via a per-repo `sentinel_exempt` flag. Nothing silently unwatched.
- Rules can also toggle which tools run per repo.

## 7. Grouped auto-fix

One open PR **per (repo, target branch)**, accumulating every approved bump, **updated in place until merged** (merge → fresh batch). No 300-PR sprawl. PR body itemizes each fix: `pkg old→new · CVE(s) fixed · severity · reachability verdict`. Uses the write-scoped git creds already stored. Human-gated. Report-only vs. auto-fix is per-repo config.

## 8. Reports

One dataset, two audiences: **exec** = posture score, counts, trend by severity/kind; **security team** = drill-down per finding (CVE, reachability verdict, remediation). Filter by repo/severity/time; export PDF/CSV/JSON; optional scheduled delivery. SBOM output included for compliance.

## 9. Data model (new tables)

- `codescan_findings` — unified: `repo, branch, kind(sca|cve|sast|license|secret|iac|sbom), identifier, current/fixed_version, tool, severity, reachability{used,reachable,exposure}, ai_verdict, action, status`.
- `codescan_policy_rules` — priority, match criteria, action, audit fields.
- `codescan_fix_batches` — one open PR per (repo, target branch); finding-id list; status; update-until-merged.
- `codescan_scan_runs` — schedule/history; **wires the existing dead `polling_enabled`/`polling_interval_minutes`/`last_poll_at` columns** in `codescan_repo_configs` + a `sentinel_exempt` flag.

## 10. Scheduling

supercronic (per house container rules — not cron) fires a daily (default, per-repo configurable) job → enqueues a posture-scan per non-exempt repo onto the existing `codescan:tasks` stream → the existing worker consumes it. Reuses the current worker/stream architecture; only the scan *type* is new.

## 11. Phasing (each shippable)

| Phase | Ships | Value |
|---|---|---|
| **P1 (MVP)** | scheduler (wire dead columns) + full-branch manifest fetch (Contents API) + SCA/CVE (deps.dev/OSV + osv-scanner) + `codescan_findings` + one report + alerts — **report-only, no AI** | the Dependabot replacement + CVE visibility |
| **P2** | full tool registry (SAST + secrets + IaC + license + SBOM) folded into findings/reports | the "3 OSS SAST tools" reports |
| **P3** | static prefilter + AI reachability/exposure triage (via WaddleAI) + policy/rules engine | smart severity-based routing |
| **P4** | grouped auto-fix PRs (git-write, itemized, update-until-merged) | the "offer to cut a fix" half |

P1 uses no AI and needs no WaddleAI — it's a self-contained Dependabot replacement. AI-assisted intelligence arrives P3, gated on WaddleAI.

## 12. Reuse vs. build (grounded in code recon)

| Capability | Today | Plan |
|---|---|---|
| Worker + stream + repo-config + git-creds + AI-provider abstraction | ✅ exists | reuse as skeleton |
| License compliance (deps.dev) | ✅ `license_scan.rs` | reuse + extend (versions + OSV advisories) |
| Outdated / CVE (SCA), SAST, reachability, scheduler, git-write, reports, policy engine | ❌ | build |
| Dead `polling_*` columns + dropped v1 `CycloneDXScanner` | scaffolded, never wired | wire / revive |

CodeScan today is **AI-only review + license compliance on PR diffs**; no scanners, no CVE, no schedule, no git-write, no reports. Sentinel is a large net-new build on the existing skeleton.

## 13. Licensing & gating

- Flag `skauswatch.codescan.sentinel` (default OFF).
- **Deterministic tool scans (SCA/CVE/SAST/license/SBOM) stand alone** at a lower tier (Professional) for customers without WaddleAI — a clean degraded mode.
- **AI-assisted capabilities** (reachability triage, AI narrative, custom policy, exec reporting) gate at **Enterprise** (they route through WaddleAI, itself Enterprise-tier) — consistent with the compliance/analytics class in the license tiers.

## 14. Open questions

- Scanner execution isolation: per-scan K8s Job vs. a bundled scanner-toolchain worker image (leaning Jobs for isolation + independent tool versioning).
- Full-branch source access for reachability: Contents-API tree fetch vs. shallow clone (leaning Contents API to stay lightweight + reuse the REST pattern).
- Report delivery channel (email / webhook / dashboard) — pick at P2.
