# DepGate — dependency scanning & caching registry (SkausWatch Registry)

**Status:** Draft design spec · **Target:** v2.1+ (net-new; not on the v2.0 cutover) · **Flag:** `skauswatch.depgate` (default OFF)

A self-hostable **secure dependency proxy + cache** ("dependency firewall"): applications in an environment point their npm / pip / docker / etc. at SkausWatch; DepGate pull-through-proxies from the public upstreams, **scans every artifact before it is cached or served**, and blocks/quarantines malicious ones. The cache half is co-equal value: a vetted internal mirror buys speed, offline resilience, and reproducibility — not just safety.

## 1. Flow

```
app (npm/pip/docker/…) ─► SkausWatch registry endpoint
  ├ cache hit + verdict tag clean ─► serve (no re-scan, no DB round-trip)
  └ miss ─► pull from public upstream (npmjs / PyPI / DockerHub / ghcr)
        ─► scan-core: ClamAV + YARA-X (malware) │ OSV/deps.dev (known vulns) │
           heuristics (install scripts, obfuscation, typosquat) │
           [optional] Socket.dev threat intel
        ─► policy: clean → cache + tag + serve · flagged → quarantine/block
```

## 2. Storage — dedicated S3 cache bucket, verdict-as-tag (GuardDuty-for-S3 pattern)

Cheapest resource-efficient design that is still secure:

- **One dedicated cache bucket** (real S3 or self-hosted MinIO — customer picks the cheapest secure store).
- **Content-addressed keys** (`sha256(artifact)`): automatic dedup (one `left-pad@1.3.0` tarball stored + scanned once for every consumer) and integrity (the key *is* the hash).
- **Verdict as S3 object tags — reusing s3scan's existing tag schema as-is** (`s3scan/scan.rs::scan_tags`): `malware`, `pup`, `threat=malware|pup|clean`, `scanTime`, `fileType` (+ `scanner-version`). The proxy reads the verdict off the object in the same call it fetches it — no DB on the hot serve path. This is s3scan's self-hosted GuardDuty-for-S3 pattern pointed at a managed bucket.
- **Lifecycle rules** evict cold artifacts on TTL; Intelligent-Tiering for the rest — bounded cost.
- **Security beyond s3scan's in-place model:** SSE-at-rest on the bucket (baseline per security.md); bucket policy where **only the scanner identity may write objects + verdict tags** (proxy/apps cannot forge `clean`); versioning/object-lock so a vetted artifact cannot be silently replaced; separate quarantine prefix for flagged artifacts.

## 3. DRY — the shared scan-core (foundation for DepGate AND Sentinel)

Recon findings (release/v2.0.x): s3scan scans **ClamAV-only** via clamd INSTREAM (`s3scan/clamav.rs::scan_bytes`); its `yara_enabled` config field is plumbed but **never invoked**; YARA-X lives only in `services/scanner`. The scan primitives (`scan_content(&[u8])`, `compute_hashes`, `detect_file_type`, `scan_bytes`) are already byte-oriented and S3-agnostic — just wired onto s3scan's `Handler`.

**Extract a unified scan-core crate** — `scan_bytes(&[u8]) → Verdict` running **ClamAV + YARA-X together**, plus the tag-writing step (`scan-and-tag(object) → verdict`):

| Consumer | Use |
|---|---|
| s3scan | customer-bucket scanning (**gains YARA-X — fixes the dead `yara_enabled` flag**) |
| scanner | malware path of ASM/scan tasks |
| **DepGate** | scan npm tarballs / wheels / OCI layers at ingest |
| Sentinel | reads the same verdict store — a package vetted at ingest is not re-scanned |

Hardening while extracting: promote the loose `scan_status VARCHAR(20)` (values enforced only in Rust) to a real enum — `clean | infected | pup | error | skipped | quarantined`.

## 4. Registry front ends (per-ecosystem protocol)

| Ecosystem | Approach |
|---|---|
| OCI/docker | CNCF Distribution / **Zot** as pull-through, or native Rust OCI API |
| npm | Verdaccio-style npm registry API (or native) |
| PyPI | devpi-style simple/JSON API (or native) |
| later | crates.io, Go module proxy, Maven, apt/deb |

Decision at build time per ecosystem: embed an OSS proxy vs. speak the registry API natively from one Rust gateway (leaning native gateway for the unified scan/policy hook + single service, using the OSS proxies as references). Upstream registry credentials (private upstreams) live in IceBox.

## 5. Scanning & intel layers (OSS off-the-shelf first)

| Layer | Tools |
|---|---|
| Malware | **ClamAV + YARA-X** (shared scan-core) |
| Known vulns | **OSV-Scanner / deps.dev / Trivy** (shared with Sentinel) |
| Package-risk heuristics | **GuardDog** (Datadog), **packj**, **OSSGadget**, Semgrep rules — install scripts, obfuscation, typosquat distance, exfil patterns |
| Images | **Trivy / Grype** on OCI layers |
| Provenance | **cosign**/sigstore verification, SLSA where published |
| **Socket.dev (optional tie-in)** | Premium threat-intel enrichment via their API — scores/alerts on top of the OSS floor. **Complement, not duplicate:** Socket ships its own firewall product; DepGate's lane is self-hosting + caching + OSS basics, Socket is the opt-in intel layer (existing relationship). Flag-gated; requires customer's Socket API key (stored in IceBox). |

## 6. Policy & quarantine

- Default: `infected` → block + quarantine prefix; `pup`/heuristic-flagged → policy decision; `clean` → serve.
- Per-environment policy rules (allow/deny lists, minimum-signal gates, "block install-scripts", tier of enforcement) — same rules-engine shape as Sentinel's (`codescan_policy_rules` precedent), audit-logged.
- Fail posture is configurable: **fail-closed** (upstream unreachable or scan error ⇒ refuse) for hardened envs; fail-open-with-alert for dev convenience. Default fail-closed for `infected`-class, fail-open for availability errors on previously-clean cached artifacts.
- Verdict TTL / re-scan: cached artifacts re-scanned when signatures/rules update materially (background sweep, not on hot path).

## 7. Relationship to Sentinel (two halves, one core)

- **Sentinel** scans dependencies you *already have* (in repos): freshness/CVE/reachability/fix-PRs.
- **DepGate** scans dependencies *entering* the environment at the gateway: malware/threat firewall + cache.
- Shared: scan-core, OSV/deps.dev layer, policy-rules shape, findings/report surfaces, WaddleAI triage (optional, Enterprise). An artifact vetted by DepGate is provenance Sentinel can trust and cite.

## 8. Data model (new)

- `depgate_artifacts` — sha256 (PK), ecosystem, name, version, upstream, size, first_seen, verdict (enum), verdict_at, scanner_version, socket_score?
- `depgate_policy_rules` — same shape as Sentinel's rules (priority, match, action, audit).
- `depgate_quarantine` — flagged artifacts + reason + disposition.
- Serve-path state lives on the object (tags); DB is the index/audit/report source.

## 9. Phasing (each shippable)

| Phase | Ships | Value |
|---|---|---|
| **P0** | **Shared scan-core extraction** (ClamAV+YARA-X unified, verdict enum, tag-writer) + s3scan adopts it (fixes dead-YARA gap) | DRY foundation; s3scan improvement lands immediately, pre-DepGate |
| **P1** | OCI/docker pull-through + scan + cache bucket + verdict tags | highest-value ecosystem, most standard protocol |
| **P2** | npm + PyPI front ends | covers the main app stacks |
| **P3** | policy/quarantine engine + package-risk heuristics (GuardDog/packj) + reports | the firewall semantics |
| **P4** | Socket.dev tie-in + provenance (cosign/SLSA) + more ecosystems (crates, Go proxy) | premium intel + supply-chain proof |

## 10. Licensing & gating

- Flag `skauswatch.depgate` (default OFF).
- Base proxy + cache + malware scan: Professional. Policy engine, Socket tie-in, provenance enforcement, AI triage (via WaddleAI): Enterprise.
- All tools OSS/OSI, non-PRC. Socket.dev integration is optional and additive — never required for the OSS floor.

## 11. Open questions

- Native Rust gateway vs. embedded OSS proxies per ecosystem (leaning native; decide with a P1 spike on the OCI API surface).
- clamd + YARA rule distribution/update cadence for the re-scan sweep.
- Multi-tenant story: shared cache with per-tenant policy, or per-tenant buckets (leaning shared cache + per-tenant policy — dedup is the whole point).
